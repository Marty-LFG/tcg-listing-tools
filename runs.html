Manifest

columns generated from the composition · empty cells are the work queue
—

A pinned bundle is excluded from lock-time chase randomisation and keeps exactly what was assigned to it — which is what lets one bundle hold the best option in every slot at once.

Seal serials

pre-assigned, before the lock
—

The serial is a committed attribute — inside the bundle’s leaf, and so inside the run root — so it has to exist before the lock even though the parcel is sealed after it. What must be unpredictable is the mapping, not the serial: a numbered commercial roll is fine as long as the assignment is random and the roll is larger than the run, so nobody holding one parcel can derive the set in play.

Amendments

append-only · never an edit
—

A locked manifest is never corrected in place. A change publishes a new header with its own anchor, and each one records the header it succeeds — so the chain is checkable by anyone holding the published artifacts, and a broken link shows without trusting us.

Lock & anchor

the commitment · irreversible · everything below happens once
—

Locking freezes this manifest, mints a verification code and a salt for every bundle, builds the encrypted blob file and computes the digest that gets timestamped into Bitcoin. None of it can be re-issued. A card found wrong afterwards needs an amendment and a new published root, so the pick-and-verify pass belongs before this button, not after it.

static files a buyer verifies against · they must outlive this LAN

The commitment and the encrypted blob go to a CDN, not to this server, because verification must not depend on us being reachable. Each is fetched back and re-hashed after upload, so what is checked is the bytes that came back rather than the ones we believe we sent.
